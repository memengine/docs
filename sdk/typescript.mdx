```bash
npm install memoryo-sdk@0.1.3
```

npm version `0.1.3` was checked on 24 November 2026. Node.js applications can use the ESM import below. Installing a package does not start the backend or enable gated features.

## Connect from your server

```ts
import { MemoryOS } from "memoryo-sdk";

function required(name: string): string {
  const value = process.env[name];
  if (!value) throw new Error(`Missing ${name}`);
  return value;
}
const memory = new MemoryOS(required("MEMORYOS_API_KEY"), required("MEMORYOS_API_URL"));
```

The constructor's **second positional argument** is the API base URL string, not an options object. It takes the backend root without `/v1`. The default is `https://api.memoryo.dev`; set it to your instance URL for self-hosting. Keep the key server-side and derive the stable `externalUserId` from authenticated application identity.

## Save and inspect the original job

```ts
const admitted = await memory.add({
  externalUserId: "synthetic-customer-123",
  conversationId: "synthetic-thread-1",
  idempotencyKey: "synthetic-thread-1-turn-1",
  messages: [{
    role: "user",
    content: "I prefer concise explanations.",
    externalTurnId: "synthetic-thread-1-turn-1",
    sourceKind: "direct_user_input",
  }],
});
if (admitted.status === "queued" && admitted.jobId) {
  const job = await memory.waitForJob(admitted.jobId, { timeoutMs: 120_000, pollIntervalMs: 1_000 });
  console.log(job.status, job.memoriesCreated, job.createdMemoryIds, job.pendingCandidatesBuffered);
} else {
  console.log(admitted.status, admitted.blockedReason);
}
```

Queued means admitted. `wasStored` is a legacy admission convenience, not proof of a stored/current record. A completed job can retain a pending candidate or create nothing. After timeout, inspect the same job; do not resubmit to hide failures. Reuse the exact authorized request/key for a network retry.

The object form accepts optional `metadata`, `source` and `preferenceClaims`. The positional form remains available:

```ts
// messages, owner, agentId?, metadata?, source?, idempotencyKey?, conversationId?
const result = await memory.add([{ role: "user", content: "I prefer concise explanations." }], "synthetic-customer-123");
```

## Retrieve and gate

```ts
const result = await memory.get({ query: "How should I explain this?", externalUserId: "synthetic-customer-123" });
if (result.memoryVisibility) {
  console.log("Context processing or unavailable; withhold dependent answer.");
} else if (result.preferenceScopeRequest || result.preferenceDecisions?.length) {
  console.log("Scope or explicit user choice required.");
} else if (result.isPassthrough) {
  console.log("Memory bypassed; apply the application's no-memory policy.");
} else {
  console.log(result.items.map(record => ({ id: record.id, content: record.content, source: record.sourceEventId })));
  // Only now consider result.systemPromptAddition for the model request.
}
```

Read properties include `items`, `hasContext`, `systemPromptAddition`, `retrievalId`, `cached`, `quotaMode`, `isDegraded`, `isPassthrough`, `memoryVisibility`, `clarification`, `sourceReviews`, `preferenceReviews`, `preferenceDecisions` and `preferenceScopeRequest`.

`get()` accepts `limit`, `categories`, `format`, `contextMaxTokens`, `timeFilterDays`, `asOf` and `preferenceContext`. Explicit preference context cannot be combined with historical `asOf` or agent-bound SDK reads. See [scoped preferences](/guides/scoped-preferences) and [visibility handling](/concepts/degradation).

## Respond to a source review

```ts
// card and selectedAction come from the displayed card and actual user choice.
const answer = await memory.answerSourceReview({
  reviewId: card.id,
  externalUserId: "synthetic-customer-123",
  version: card.version,
  action: selectedAction,
});
console.log(answer.resolved, answer.nextStep);
```

`keep_current` and `dismiss` close an eligible review without storing pending text. `restate` returns `resolved: false`, `nextStep: "add_memory"` and requires a separate new save. Intentional typed replacement needs the actual target ID/version; see [the replacement contract](/guides/scoped-preferences). A model must not invent a user's choice or replacement binding.

Source review is separate from `answerClarification()` and administrative service correction. See the [native source-review contract](/api-reference/retrieve#review-an-uncertain-source-statement-in-your-existing-chat).

## Registered service events

```ts
const source = MemoryOS.source("billing-service", {
  eventId: "synthetic-subscription-event-1",
  observedAt: "2026-11-24T09:00:00Z",
  scope: { account_id: "synthetic-account-1" },
});
```

Pass `source` to `add()` only after the owner configures the writer, credential binding and authority policy. Normal chat applications can omit it. See [provenance](/concepts/provenance).

## Other contracts

- `getJobStatus()` / `waitForJob()`: original job inspection.
- `list()`: authorized management listing; use the native history endpoint for version history, not as current answer context.
- `feedback()`: retrieval outcome reporting; corrections may create another asynchronous job.
- Delete/export and domain helpers: require their endpoint-specific permissions/configuration.

`UniversalMemoryOS` belongs to disabled-by-default Memory Passport. Assistant-proposal confirmation and automatic interpretation are experimental. Check the feature configuration of your backend before using optional contracts.
