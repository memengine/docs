MemoryOS MCP exposes backend operations as tools. The MCP gateway and the native API are separate services: a working native SDK does not prove that a gateway is running or that its tool schema matches the installed backend.

## Pick an access mode

| Mode | Identity and credentials | Use |
| --- | --- | --- |
| Public authenticated gateway | Signed-in user/workspace; tenant and owner resolved server-side | Multi-user MCP clients |
| Private sidecar | Server-side workspace API key; trusted caller supplies owner IDs | Local/server integrations under your control |

Public MCP authentication is separate from Memory Passport. Universal-memory features remain disabled by default; do not enable them for ordinary tenant use.

## Connect your MCP client

Connect your MCP client to your MemoryOS gateway URL and complete its sign-in flow. Verify the installed `tools/list` schema before using optional scope/review fields. If a required tool is absent, report the integration blocker rather than sending raw requests or falling back to another identity.

## Public self-scoped flow

1. Sign in to the account and workspace.
2. Use `memoryos_remember` for authorized conversation evidence. Reuse a stable key only for an identical retry.
3. Poll the returned original job with `memoryos_my_job_status`.
4. Read with `memoryos_my_context`, supplying explicit typed scope when needed.
5. Honor visibility and unresolved-choice signals before model inference.
6. Present source-review cards separately, then submit the user's offered action with `memoryos_answer_source_review`.

These tools do not accept an arbitrary `external_user_id`. A project selector is preference applicability, not a way to change the user or gain project access.

### Explicit scoped inputs

`memoryos_remember` accepts `messages`, optional `idempotency_key`, `conversation_id` and `preference_claims`. Each claim supplies `property_key`, `value`, `applicability`, `turn_index` and `quote`, plus replacement/choice fields when applicable.

`memoryos_my_context` accepts `query`, retrieval options and optional `preference_context`. The backend must enable explicit preferences; supplying fields in an adapter alone is insufficient. See [the native contract and field examples](/guides/scoped-preferences).

Conversation text remains client-asserted evidence. Role labels, metadata or tool arguments do not grant higher authority or prove user consent. Do not relabel tool output or documents as user speech.

### Versioned source-review decisions

When a response supplies `source_reviews`, display its question and offered actions to the user. Call:

```json
{
  "review_id": "<id from the displayed card>",
  "version": "<opaque version from the same card>",
  "action": "keep_current"
}
```

The tool is `memoryos_answer_source_review`. Use only the actual user's selection. `keep_current` and `dismiss` close eligible reviews without activating pending text. `restate` requests a new statement/save; it is not an applied correction. Retrieve again to verify closure/current recall.

The self-scoped backend route is `POST /v1/mcp/tenant/source-reviews/{review_id}/answer`, with `version` and `action`; identity is derived from authenticated context. It wraps the versioned native review service. The A/B tool `memoryos_answer_clarification` is a different queue and cannot answer a source-review card.

### Holds and safe projection

During an affected-context hold, review cards can remain available separately while facts remain withheld. Never put review previews, pending values or card text into current-record context or a model prompt as accepted facts. Check the gateway's projected response rather than assuming it has the full native HTTP envelope. Follow [visibility handling](/concepts/degradation).

Public mode restricts generic owner-selecting tools and raw API requests. Do not use `memoryos_api_request` as an escape hatch around missing self-scoped tools or authorization.

## Private sidecar setup

Install the adapter build supplied for your environment. If working from the supplied adapter repository:

```bash
pip install -e .
```

Configure only in that private process:

```bash
MEMORYOS_API_KEY=<synthetic workspace key>
MEMORYOS_API_URL=<your native API root>
```

Then run `memoryo-mcp` using the installed command. Native `MEMORYOS_API_URL` is not the gateway's `/mcp` address. Private generic tools include `memoryos_add_memory`, `memoryos_get_context` and `memoryos_get_job_status`; check the actual schema and grant only the required permissions.

Do not expose a tenant-key sidecar through public ingress. Public deployments require their own validated OAuth/Clerk configuration and self-scoped surface, not an API key in client browser settings. This page does not deploy/configure a public gateway.
