Before sending users to a consent page, explain what's happening. Don't let them discover MemoryOS on their own mid-flow.

## What to tell users

Use plain language. Introduce **Memory Passport** as the place where users approve, review, and revoke access.

Suggested copy:

> We use MemoryOS so you can choose which AI apps may remember and use your approved context. You can review, narrow, or revoke access any time from the MemoryOS permission center.

Show this in at least one of: onboarding, settings/integrations, or the screen where the user clicks "Connect shared memory."

## Generate the consent URL

```python
from memoryos.universal import UniversalMemory

consent_url = UniversalMemory.consent_url(
    agent_id="your_global_agent_id",
    state="optional_user_session_state",
    categories=["preference", "goal"],
)
```

`categories` preselects the memory categories for this specific consent link. If omitted, MemoryOS uses the global agent's defaults. The user can still add or remove before approving.

## With app-owned callback

Use a `redirect_uri` when your app needs to update its own UI after consent — for example, showing "Memory connected" in your settings page.

```python
consent_url = UniversalMemory.consent_url(
    agent_id="your_global_agent_id",
    redirect_uri="https://yourapp.com/integrations/memoryos/callback",
    state="secure_random_state_token",
    categories=["preference", "fact"],
)
```

Your callback must:
- verify `state` server-side and mark it as consumed
- handle `status=granted` and `status=denied`

Callback templates: `examples/production-memoryos-callbacks/`

If you don't need your app to react immediately, omit `redirect_uri`. MemoryOS shows a hosted completion page after approval.
