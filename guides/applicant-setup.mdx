Use this guide alongside your assignment. It explains access and integration; your assignment defines the work and submission deadline.

## Access you need

The assessment owner must supply:

- A reachable API base URL and an assigned synthetic workspace. Hosted access is pending launch; do not assume the SDK's default URL is available.
- A synthetic-only API key with the required `read` and `write` permissions, delivered privately. No administrator key is needed for a normal integration.
- A stable test-owner naming convention and the enabled features/property catalog, if scoped preference tests are assigned.
- A provider budget or an approved substitute, and an operator contact for administrative review cases.
- Dashboard or MCP access only if that surface is part of the assignment. An API key does not sign you into the dashboard; a dashboard login does not create a working API key automatically.

If these are missing or fail, report **blocked** with the first failure. You do not need to deploy MemoryOS to AWS or repair its backend to complete an honest assessment. The no-key [simulation](/quickstart) is available while access is pending; label it as simulation.

## First real journey

1. Record your SDK/runtime version and assigned API address, without credentials.
2. Use one fresh synthetic owner. Resolve it on your application server after authentication; preserve it across sessions and clients.
3. Submit one authorized statement. Record the original job ID, admission status and eventual job result.
4. Retrieve, inspect visibility first, then verify actual returned IDs, content and provenance. Do not count `queued` as stored or `completed` as correct recall.
5. Reopen the application and retrieve using the same owner. A new conversation ID should not create a new person.
6. Follow the assigned correction/review path, then verify current and previous state. Keep review questions and actions inside the existing chat.

The [quickstart](/quickstart) provides SDK examples. [Visibility handling](/concepts/degradation) explains when a dependent model answer must stop. [Scoped preferences](/guides/scoped-preferences) explains explicit project selection; project names in free text are not a substitute.

## Features in plain language

| Feature | What your application does |
| --- | --- |
| Persistent memory | Save authorized evidence and recall the same owner's context in a later session |
| Provenance | Retain source event/memory IDs so a reviewer can trace a returned fact |
| Scoped preferences | Supply the exact property/value/applicability, and select the intended scope on reads |
| Visibility hold | Show processing/unavailable status and stop answers/actions that depend on withheld context |
| Source review | Present the returned versioned card and send the user's selected action |
| Service authority | Use owner-configured service writers; metadata cannot grant your client extra authority |
| Retry handling | Reuse the same authorized request and idempotency key after a network failure |

Not every feature is enabled in every environment. Source reviews, A/B clarification, typed preference review and administrative service correction are distinct contracts. Ask the owner for the assigned path rather than bypassing one with another.

## What to submit

Separate setup time from integration/debugging time. Record versions, the first failure, workarounds/custom code and outcomes as **passed, failed, blocked or not attempted**. Include redacted request/job IDs and evidence links. Distinguish mocked behavior, actual backend calls and actual model answers.

Honest negative feedback is useful: say what MemoryOS saved you, what it added, and whether you would instead implement the same behavior in your own database/service. AI assistance is allowed when declared; you remain responsible for checking the result.

Never include API keys, tokens, `.env` files, real customer data or private database dumps. Do not clear queues, change policies or deploy/repair the backend to work around a failure. Send the first reproducible failure to the assessment owner.
