## Decision guide

| Building | Use |
| --- | --- |
| Chatbot, assistant, copilot, coding agent, SaaS personalization | General Engine |
| Tutoring, exam prep, learning app, student dashboard | EdTech Schema |
| Support bot, support copilot, helpdesk platform | Support Schema |
| HR, healthcare, agriculture (not yet available) | General Engine — migrate when the domain ships |

**General Engine** — prompt-ready memory, no schema setup needed. The right default.

**EdTech** — adds structured student memory: grade level, curriculum, weak/strong topics, exam context, learning style, forgetting stages. Use it when your UI needs student profile data or when the AI should adapt to the student's knowledge state.

**Support** — adds structured support memory: customer identity hints, open issue, issue history, resolution preference, sentiment, escalation risk. Use it when support context needs to carry across conversations and tickets.

## Integration rule

Don't branch your main model-call path by domain. MemoryOS decides what's in `system_prompt_addition` based on the tenant setting.

```python
result = mem.get(
    query=current_task,
    external_user_id=external_user_id,
    context_max_tokens=700,
)

system_prompt = BASE_PROMPT
if result.has_context:
    system_prompt = f"{system_prompt}\n\n{result.system_prompt_addition}"
```

## When to use profile endpoints

`get()` is for model calls. Domain profile endpoints are for dashboards and admin UI.

| Need | API |
| --- | --- |
| Prompt context for an AI response | SDK `get()` |
| Store conversation memory | SDK `add()` |
| Student profile UI | `GET /v1/memories/edtech-profile` |
| Support customer dashboard | `GET /v1/tenant/customers` |
| Tenant domain settings | `GET/PATCH /v1/tenant/domain-schema` |
